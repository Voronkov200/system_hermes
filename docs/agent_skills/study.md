# Hermes Skill: Учёба 11 класса

## Назначение

Skill описывает устойчивый учебный workflow Hermes на Android. Он работает вместе с
детерминированным `StudySkillRouter`: модель формулирует ответ, но приложение выбирает
режим учебной работы.

## Источники

1. Локальный учебник/PDF на телефоне — первичный источник содержания.
2. Сохранённые параграфы и страницы — первичный источник для повторения.
3. `resheba.top` — внешний справочник для проверки заданий и поиска решений.
4. Веб-поиск — только когда локального источника недостаточно.

При конфликте источников сначала сообщай о конфликте и отдавай приоритет локальному
учебнику для объяснения материала.

## Основной цикл обучения

`объяснение → практика → проверка → ошибка → повтор → mastery → интервальное повторение`.

Открытие параграфа или ручная галочка `learned` не должны сами по себе давать 100% mastery.
Mastery изменяется после проверки ответа. Слабые темы сохраняются отдельно от текста
учебника и переживают обновление bundled-контента.

## Workflow

1. Определи предмет, класс и точную тему/номер задания.
2. Проверь локальный `study/` и сохранённые страницы перед интернетом.
3. Для PDF читай только нужные диапазоны; большие документы дели на части.
4. Сначала объясни тему своими словами.
5. Затем дай определения, правила/формулы, типовые ошибки и алгоритм.
6. Для задач: условие → ход решения → ответ → короткая проверка.
7. Для практики сначала задавай вопросы/задачи без ответов.
8. После ответа пользователя классифицируй результат как `correct`, `partial` или `incorrect`.
9. Записывай mastery и слабые темы через локальный learning service.
10. Если ответ неверен — объясни ошибку и назначь повторение раньше следующего интервала.
11. Для экзамена смешивай темы и не показывай ответы до попытки пользователя.
12. ГДЗ используй как проверочный внешний источник, а не как замену обучению.
13. Не выдумывай номер задания, страницу, ответ или содержимое книги.
14. При отсутствии OCR сообщи об ограничении и предложи импорт OCR/PDF с текстовым слоем.
15. Сохраняй PDF-конспект только по запросу или при явной необходимости.

## Режимы

- `explain` — объяснить тему.
- `learn` — провести учебную сессию с проверкой понимания.
- `practice` — дать задания и проверить ответы.
- `review` — повторить слабые и просроченные темы.
- `solve` — разобрать конкретную задачу по шагам.
- `gdz_check` — сверить решение с ГДЗ и указать расхождения.
- `exam` — мини-экзамен без подсказок до попытки пользователя.

## ГДЗ

Перед запросом ГДЗ нормализуй: предмет → учебник/автор → класс → номер задания.
Если конкретный учебник определить нельзя, не выбирай решение наугад.

ГДЗ можно использовать для:
- сверки конечного ответа;
- проверки отдельных шагов;
- поиска расхождения между решением пользователя и эталоном.

ГДЗ нельзя использовать как доказательство того, что пользователь понял тему.

## Безопасность агента

- Инструменты не получают разрешения от LLM. Каждый вызов проходит `AgentToolPolicy`.
- READ-инструменты разрешаются автоматически.
- WRITE разрешён только для безопасных рабочих путей; остальные требуют подтверждения.
- DELETE/RESET и чувствительные действия требуют явного подтверждения.
- При отсутствии callback подтверждения чувствительное/опасное действие блокируется.
- Не удалять пользовательские учебники, конспекты и прогресс при обновлении bundled-контента.
- Не писать API-ключи, токены или приватные данные в журнал.
- Не утверждать, что действие выполнено, если tool не вернул успех.

## Android / offline

Приоритет: локальное содержимое, кэш и экономия трафика. Сетевой запрос должен быть
отменяемым и иметь timeout. Отсутствие сети не должно ломать просмотр уже импортированного
учебника или локального прогресса.
