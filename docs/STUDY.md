# Модуль «Учёба» — архитектура, источники и проблематика

## Цель

«Учёба» в System Hermes — это не каталог PDF и не отдельный экран ГДЗ. Модуль должен превращать официальные школьные материалы в полноценный учебный цикл:

```text
официальный источник
→ правильная привязка к параграфу
→ удобное чтение
→ структурированный конспект
→ практика / ГДЗ
→ active recall
→ интервальное повторение
→ долговременное запоминание
```

## Предметы

В интерфейсе представлены 15 предметных направлений:

- Беларуская мова
- Русский язык
- Английский язык
- Беларуская літаратура
- Русская литература
- История Беларуси в контексте всемирной истории
- Обществоведение
- География
- Алгебра
- Геометрия
- Физика
- Химия
- Биология
- Информатика
- Астрономия

Английский язык и история используют по две части учебника, поэтому в основной очереди — 17 PDF.

Хрестоматии и сборники не входят в обязательную автоматическую загрузку.

## ГДЗ

Источник:

- https://resheba.top/gdz/11-klass

Логика:

```text
предмет
→ раздел
→ номер задания
→ оригинальное изображение решения
→ локальный кэш
```

Hermes не должен превращать точное решение в ненадёжный OCR, если оригинальное изображение доступно.

## Проблема 1: PDF не является готовым мобильным интерфейсом

Официальные материалы поставляются в PDF. Для мобильного приложения это создаёт проблемы:

- крупные файлы;
- сетевые тайм-ауты;
- необходимость быстро перейти к конкретной странице;
- нестабильность отображения сложных шрифтов и формул;
- неудобство повторного открытия без сети.

Поэтому используется схема:

```text
официальный PDF
→ нужная страница
→ рендер в PNG высокого разрешения
→ локальный кэш
→ Image + zoom / pan
```

PNG-кэш улучшает стабильность UI и офлайн-доступ, но не является независимым PDF-рендерером: если сам renderer ошибочно отображает конкретный символ, следующий шаг — другой renderer или заранее подготовленные изображения страниц.

## Проблема 2: OCR нельзя использовать как источник точных формул

Текстовый слой PDF и OCR могут портить:

- степени;
- корни;
- дроби;
- индексы;
- греческие символы;
- геометрические обозначения;
- знаки сравнения и специальные символы.

Для гуманитарного текста небольшая ошибка может быть терпимой. Для формулы один символ меняет смысл.

Правило:

> OCR используется для поиска и структуры, но точные формулы, схемы и сложная математическая запись проверяются по оригинальной странице официального учебника.

## Проблема 3: часть учебников могла не попасть в очередь

Ранее автоподготовка зависела от уже загруженных локальных subject/paragraph данных. Если локальная база ещё не была полностью подготовлена, часть bookId могла не попасть в очередь.

Требование новой архитектуры:

- полный список 17 основных PDF известен заранее;
- они ставятся в очередь независимо от состояния локальной миграции;
- хрестоматии не блокируют основные книги;
- при сетевой ошибке разрешён безопасный повтор;
- интерфейс не блокируется на время загрузки.

## Проблема 4: печатная страница и PDF-страница различаются

Из-за обложек, титульных листов и содержания печатная страница 42 может физически находиться на другой PDF-странице.

Поэтому для каждой книги хранится `pageOffset`.

Связь параграфа строится так:

```text
paragraph
→ bookId
→ printed page
→ pageOffset
→ pdf page
```

## Проблема 5: длинные изображения ГДЗ

Некоторые решения имеют экстремальную высоту. Если использовать `BoxFit.contain` в области размером с экран и пытаться показать всё изображение целиком, решение превращается в узкую нечитаемую полосу.

Правильный viewer:

- начальный размер примерно по ширине экрана;
- начало изображения сверху;
- вертикальная прокрутка длинного решения;
- pinch-to-zoom;
- pan при увеличении;
- переход к предыдущему/следующему заданию;
- отсутствие огромных пустых полей вокруг документа.

## Проблема 6: одного чтения недостаточно

Цель Hermes — не «открыть PDF», а провести пользователя через учебный цикл:

```text
прочитал
→ выделил главное
→ сформировал структуру
→ проверил себя
→ решил задачу
→ сохранил ошибку
→ повторил позже
```

Поэтому экран параграфа содержит четыре вкладки:

- Конспект
- Учебник
- ГДЗ
- Повторение

## Предметные конспекты

Один универсальный шаблон не подходит разным дисциплинам.

Ключевые цепочки:

- История: `причина → событие → результат → последствия`
- Алгебра: `понятие → формула → ОДЗ → алгоритм → проверка`
- Геометрия: `чертёж → дано → теорема → доказательство → ответ`
- Физика: `явление → закон → величины → формула → применение`
- Химия: `вещество → свойство → реакция → продукт → применение`
- Биология: `условия → процесс → результат → значение`
- Информатика: `задача → данные → алгоритм → программа → тест → исправление`
- Астрономия: `наблюдение → объяснение → закон → практическое значение`

Для языков, литературы, обществоведения и географии используются свои структуры.

Важно: факты для конспекта должны опираться на исходный учебный материал. Если надёжного фрагмента нет, лучше оставить поле пустым и предложить обратиться к оригинальной странице, чем генерировать выдуманный факт.

## Личные данные ученика

Хранятся отдельно от учебного контента:

- собственный пример;
- мини-вывод;
- что непонятно;
- дополнение учителя;
- собственные ошибки.

Это защищает данные пользователя от сброса при обновлении учебного каталога.

Маркеры:

- `!` — важно
- `?` — непонятно
- `Д` — дата
- `Ф` — формула
- `П` — правило / понятие
- `О` — ошибка
- `ПВ` — повторить

## Active Recall и интервальное повторение

Используемая цепочка:

```text
10–15 минут
→ 1 день
→ 3–4 дня
→ 7 дней
→ 30 дней
```

Повторение должно включать 3–5 вопросов, на которые пользователь сначала отвечает по памяти, а уже потом сверяется с материалом.

## Офлайн-архитектура

Локально должны сохраняться:

- скачанные PDF;
- подготовленные PNG страниц;
- каталог ГДЗ;
- уже открытые изображения решений;
- учебные данные;
- пользовательские заметки;
- ошибки;
- состояние повторений.

При потере интернета ранее загруженные материалы должны оставаться рабочими.

## Архитектурный принцип источников

Источники истины разделены:

| Данные | Источник |
|---|---|
| Учебные факты | официальный учебник |
| Точные формулы / схемы | оригинальная страница официального учебника |
| Решения задач | оригинальное изображение Resheba |
| Личные мысли | пользователь |
| Прогресс / повторения | локальное состояние пользователя |

AI не должен смешивать эти категории.

## Что нельзя делать

- придумывать учебные факты при отсутствии источника;
- выдавать повреждённый OCR формулы как точную запись;
- полностью зависеть от интернета;
- загружать все дополнительные сборники раньше основных книг;
- ужимать длинный ГДЗ целиком по высоте экрана;
- удалять личные заметки вместе с техническим кэшем;
- использовать один и тот же конспект для всех предметов;
- считать «прочитал» равным «выучил».

## Целевой результат

Модуль должен отвечать на четыре вопроса пользователя:

1. Что я изучаю сейчас?
2. Где находится исходный материал?
3. Понял ли я тему и могу ли воспроизвести её без учебника?
4. Когда мне нужно повторить её снова?

Итоговая задача — превратить разрозненные PDF, изображения решений и локальные записи в одну надёжную персональную систему обучения.
