# Каталог данных «Покупок» — контракт для издателя

Этот каталог — **общий мост** между источником (агент, распознающий чеки из
Telegram-бота) и приложением (потребитель). Приложение НЕ пишет сюда — только
читает по raw-ссылке. Публикует — агент.

Схема потока:

    фото чека в бот → агент: OCR → правка data/receipts.json → git push
                                                          ↓
    приложение: запуск / pull-to-refresh / таймер 24ч → pull → upsert → «Покупки»

## Файлы

| Файл | Что содержит | Читает |
|---|---|---|
| `receipts.json` | массив распознанных чеков | блок «Покупки» |
| `prices.json` | массив цен `{shop,name,price,old_price?,discount?,date}` | блок «Цены» |

Оба хранятся в `Voronkov200/system_hermes`, ветка `main`, папка `data/`.
Raw URL: `https://raw.githubusercontent.com/Voronkov200/system_hermes/main/data/`.

## Формат записи чека (`receipts.json`)

```json
{
  "store": "ТРОЙКА",
  "address": "ул. Крупской, 119",
  "dateTime": "21.07.2026 12:52",
  "total": 11.58,
  "discount": 0,
  "paymentMethod": "карта",
  "sourceType": "ocr",
  "confidence": 0.93,
  "items": [
    { "name": "Пакет майка", "qty": 1, "unitPrice": 0.29, "amount": 0.29 }
  ]
}
```

Поля:
- `store` — обязательно; название магазина.
- `address` — необязательно.
- `dateTime` — `DD.MM.YYYY HH:mm` (приложение парсит и этот, и похожие форматы).
- `total` — ИТОГО чека (BYN), число.
- `discount` — скидка, 0 если нет.
- `paymentMethod` — «карта» / «Наличные» и т.п.
- `sourceType` — `ocr` (распознание фото) и т.п.
- `confidence` — уверенность распознания, число 0..1.
- `items` — массив позиций `{name, qty, unitPrice, amount}`.

## Правило честности (обязательно)

Если позиция, цена, номер или сумма **не читаются** — НЕ выдумывай. Ставь
`confidence` ниже 0.8 (или не ставь вовсе). Приложение при `confidence < 0.8`
само помечает чек как «требует проверки» (плашка в карточке чека). Это правило
из инструкции: фиксируем факты, а не предположения.

## Как опубликовать новый чек

1. Прислать фото в бот → распознать (OCR) → собрать запись в формате выше.
2. Вставить запись в конец массива в `data/receipts.json` (валидный JSON).
3. `git add data/receipts.json && git commit -m "receipt: <магазин> <сумма>"` →
   `git push origin main`.
4. Приложение подтянет при следующем триггере (запуск / refresh / 24ч / кнопка).

## Дедупликация

Приложение не создаёт дубль, если чек с теми же `store + dateTime + total` уже
есть (не важно, откуда он пришёл). Поэтому не нужно бояться, что каталог
пересечётся с ранее сохранёнными чеками — повторы отфильтруются.

## Отметить деградацию

Если распознание стабильно плохое — лучше снизить `confidence`, чем подгонять
цифры. Валидный JSON обязателен: повреждённый `receipts.json` приложение
отбросит целиком (покажется ошибка синка), а не «починит» частично.
